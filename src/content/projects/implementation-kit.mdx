## The problem

A shared import tool for two fictional CRM deployments, with versioned mappings, dry runs, repeat-safe apply, and partial rollback.

## The engineering decision

Put repeatable customer differences in configuration. Bind a run to its tenant and mapping version, and roll back only the records that run still owns.

## What you can verify

The North import writes two records, then writes zero on replay. Rollback removes one record and preserves the record changed by an operator; Harbor’s records remain intact.

[Inspect the recorded evidence](https://github.com/Vishvendra07/implementation-kit/blob/main/evidence/demo.json) · [Read the source and run locally](https://github.com/Vishvendra07/implementation-kit)

## Scope and tradeoffs

Both deployments and the CRM are simulations backed by a local sandbox. No customer CRM is changed.

The repository includes setup instructions, automated tests, and a GitHub Actions workflow. Recorded local evidence and current hosted CI are separate signals; the repository shows the latest run status.
