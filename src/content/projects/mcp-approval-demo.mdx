## The problem

A stdio MCP server that separates a proposed catalog change from the operator command that applies it.

## The engineering decision

Bind the approval to the exact payload digest and expected record revision. Keep proposal and approval entry points separate and persist a receipt.

## What you can verify

The recorded run proposes a quantity change without changing the catalog, then applies the reviewed proposal: quantity moves from 5 to 8 and revision from 1 to 2.

[Inspect the recorded evidence](https://github.com/Vishvendra07/mcp-approval-demo/blob/main/evidence/demo.json) · [Read the source and run locally](https://github.com/Vishvendra07/mcp-approval-demo)

## Scope and tradeoffs

Synthetic inventory and local SQLite. The file needs OS access controls in a shared environment; the demo is not a hosted authorization service.

The repository includes setup instructions, automated tests, and a GitHub Actions workflow. Recorded local evidence and current hosted CI are separate signals; the repository shows the latest run status.
